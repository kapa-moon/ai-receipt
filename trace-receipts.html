How the receipt works

1. Read each provider's trace. Ignore cumulative token counters; deduplicate model responses. Separate user prompts from tool results and system messages.

2. Normalize input into fresh input, cache reads, cache writes and output. Reasoning is a subset of output; never add it a second time.

3. Multiply token categories by their corresponding public API rate. For OpenAI, show standard-speed short/long-context scenarios because this importer does not resolve the context tier. Claude uses recorded cache duration; missing duration creates a range. These are current-rate scenarios, not historical invoices.

4. Assign each model response to a user turn. Infer a provisional intent category from the prompt with local rules, then let you correct it. Tool calls are correlated within the response/turn; tool-associated costs overlap.

5. Ask you what was useful, what still needs work, and what result provides evidence. These answers do not alter measured token usage.

Codex exec expressions identify attempted nested invocations, not guaranteed successful execution. Built-in web/search billing and compute fees cannot be recovered reliably from these wrappers, so OpenAI dollar estimates cover model tokens only. Claude server web-search counts, when explicitly recorded, are rated at $0.01/search. Other tool fees are not included.
