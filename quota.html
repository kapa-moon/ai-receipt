Subscription capacity

How much room is left to work—not how much you owe.

Account-wide, not project-specific. Quota percentages are provider-reported observations. They cannot be calculated reliably from tokens or assigned to a single task when other work is happening. No quota is assumed for a plan that does not report one.

Long-window history

Dots are observations. Steps connect nearby observations only. Gaps over 30 minutes, decreases and changed reset times are not joined. Reset markers are reported timestamps—not proof of a refill. Charts end at the latest observation; the dashboard does not invent subsequent usage.

What can this tell you?

Capacity leftWhich window is closest to its limit?
Reset timingWhen should you check capacity again?
Usage patternWhich work periods coincide with quota rises?

A rise is percentage points of the reported allowance, not dollars. Sparse observations cannot establish how much a task consumed. This version does not predict time-to-exhaustion or treat pace as a target.

Record an observation

Copy values from your provider's usage screen. Leave an unreported window blank. Record the displayed reset time, rather than assuming a continuously replenishing rolling limit.

A historical snapshot is not a live balance. A passed reset time means refresh is needed; it does not automatically change the stored percentage to zero.

Sources and scope

Official OpenAI pricing and usage-limit guidance distinguishes subscription allowances from API token prices. Windows depend on plan; local and cloud agent work can share an allowance. Ordinary ChatGPT features may have separate limits; this is not a universal meter for every chat.

Imports accept Codex rollout JSONL with recorded rate-limit fields, provider snapshot JSON, or exported quota history. No authenticated provider polling is implemented in this static file. Refresh by importing another observation or adding one manually. History is stored in this browser and exported on request.
